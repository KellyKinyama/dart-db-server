# Parity report — engine vs. real Oracle/MySQL sample schemas

Generated by loading the real downloaded sample schemas through the shared
engine via the harness in [`../test/parity/`](../test/parity). Reproduce with:

```powershell
dart test test/parity/ -r expanded
```

> **What this measures.** Each dataset's `.sql` dump is split into statements and
> executed against `Database.open()`; the harness tallies how many the engine
> accepts and groups the rejections. It is a *dialect-ingestion* signal (can the
> engine load a stock Oracle/MySQL dump as-is), not a correctness benchmark.

**Run date:** 2026-10-21 · **Datasets:** see [`test-data.md`](test-data.md)

## MySQL — employees (`test_db`) ✅

All 6 base tables materialized: `departments`, `dept_emp`, `dept_manager`,
`employees`, `salaries`, `titles`. A seeded join + aggregate returned the
expected result:

```sql
SELECT e.last_name, MAX(s.salary) AS top
FROM employees e JOIN salaries s ON e.emp_no = s.emp_no
GROUP BY e.last_name ORDER BY top DESC;
-- → [[Lovelace, 95000], [Turing, 80000]]
```

**Rejections (expected, non-blocking):**
- `source load_*.dump` (9×) — MySQL CLI directive, not server SQL. Data lives in
  separate `.dump` files; the harness seeds rows by hand instead.
- `SELECT '...' AS 'INFO'` (3×) — single-quoted column alias not parsed.
- `flush … logs`, `DROP TABLE a, b, c` (multi-target drop).

## MySQL — sakila ⚠️

0 tables loaded. **Every** sakila `CREATE TABLE` uses `INT UNSIGNED`, which the
engine's parser rejects:

```
FormatException: Expected ) but got "UNSIGNED"
```

Secondary rejections: `DROP SCHEMA` / `CREATE SCHEMA` (`CREATE … after CREATE`).

## Oracle — HR ⚠️

0 tables loaded (after SQL*Plus `rem`/`SET`/`Prompt` directives were stripped by
the harness). Blocking gaps:
- `COMMENT ON …` (41×) — unsupported statement.
- Inline **named column constraints** — `col NUMBER CONSTRAINT x NOT NULL`
  (`Expected ) but got "CONSTRAINT"`).
- `ALTER TABLE … ADD ( CONSTRAINT … PRIMARY KEY (…) )`
  (`Expected name but got "("`).
- Cascading `No such table` once the parent `CREATE TABLE` fails.

## Prioritized engine gaps (surfaced by this run)

Ranked by parity leverage — each lands in the shared engine and benefits both
wire front-ends at once (see [`../doc/parity-roadmap.md`](../doc/parity-roadmap.md)).

| # | Gap | Unblocks | Est. size |
| --- | --- | --- | --- |
| P1 | Accept `INT/BIGINT … UNSIGNED` type modifier | all of sakila + most MySQL dumps | S |
| P2 | Oracle inline named constraints (`CONSTRAINT x NOT NULL`) | Oracle HR/OE/SH schemas | M |
| P3 | `COMMENT ON TABLE/COLUMN …` (accept, optionally no-op) | every Oracle sample schema | S |
| P4 | `ALTER TABLE … ADD (CONSTRAINT … PRIMARY KEY …)` | Oracle schemas using out-of-line PKs | M |
| P5 | `CREATE/DROP SCHEMA` (alias of database) | sakila + MySQL dumps | S |
| P6 | Single-quoted column alias `SELECT x AS 'y'` | MySQL dump `INFO` probes | S |

> These are **observations for the engine owner**, captured here without
> modifying any engine code. The harness will re-measure automatically as the
> gaps close.
